# 판정 기준 review-v2와 긴급 표현 처리

2026-11-13. 결과 칸의 완료·중단·수신 거절과 해당 상태 전환은 유지한다. 예약과 119 전화 버튼은 없다.

새 통화는 항목별 0~3점(전체 최대 15점)을 사용한다. 부정 신호 없음/해당 없음 0, 일시적·가벼운 불편이 명시된 경우 1, 반복·지속이 명시된 경우 2, 생활 지장·도움 필요가 명시된 경우 3이다. 일반 부정만으로 점수를 확정하지 않고 최대 두 번 정도를 묻는다. 미확인은 점수를 null로 저장하고 해석 실패·본인 미확인·정도 미확인·음성 인식 실패·미응답을 구분한다. 반대 내용이 정정 단서 없이 나오면 충돌로 남긴다. 항목은 사전으로 관리해 중복 합산하지 않는다.

합계 1~2는 추가 확인, 3~15는 우선 확인이다. 일부 미확인이 있어도 확인된 추가/우선 판정을 유지한다. 합계가 0이어도 정도 미확인인 부정 신호가 있으면 정보 부족이다. 모두 미확인이면 점수 산정 불가이며, 나머지가 부정 신호 없이 확인됐다면 확인된 범위에서 특이 표현 없음이다. 수신 거절·중단 가산은 없다. 점수와 확인 개수는 별개이며 이 기준은 임상 검증되지 않은 시연용이다.

확인 우선순위 칸은 판정/점수와 사유/확인 개수의 두 줄을 쓴다. 상세에 항목별 원문 근거·점수 또는 null·사유·버전을 표시한다. 기존 결과 칸은 수정하지 않았다.

119 불러줘·구급차 보내줘·응급차 좀 불러주세요·현재 위험 표현은 일반 질문을 멈추고 즉시 안전 안내한다. 119 단독은 안내부터 제공하지만 emergency_state=possible로 남기고, 명확한 요청은 confirmed로 구분한다. 두 상태 모두 일반 점수와 독립 표시하며 새 기준의 100점은 없다. 부정·과거·인용·일반 질문을 별도로 검사한다. 일시정지는 통화 종료까지 유지하며, 모호한 답변이나 STT 실패로 안전 상태를 자동 확정하지 않는다. 실제 신고나 의료적 진단을 수행하지 않는다.

안내: “긴급한 상황이면 지금 직접 119에 연락하거나 가까운 분에게 도움을 요청해 주세요. 안심온은 실제 신고를 하지 않습니다.”

## 저장과 호환

기존 시작 백업 후 call_reviews 테이블을 추가한다. 기존 native 기록은 변경 전 계산기(legacy_priority.py)로 당시 저장된 답변에 대한 이전 기준 결과를 한 번 스냅샷하고 고정한다. 원래 점수가 별도로 저장되지 않았던 native 기록은 이 마이그레이션 시점의 기존 계산 결과다. 가져온 기록은 원래 JSON과 점수를 유지한다. 이전에 진행 중이던 통화는 기존 대화 규칙으로 종료하며 종료 시 기존 기준으로 결과를 확정한다. 새 통화만 review-v2를 쓴다.

새 분석과 리뷰 JSON은 기존 답변 트랜잭션 안에서 함께 저장한다. 각 항목은 버전·분류·근거·확인 점수/미산정 사유를 포함한다. 원문과 저장 시각은 기존 시도/분석 이력에도 남는다. 음성 인식 오류는 별도 input-events API로 남겨 실제 답변으로 조작하지 않고 문항을 진행시키지 않는다.

이전 기록에는 ‘이전 기준’을 표시하고 새 최대 15점과 구분한다. 우선순위 정렬은 긴급 여부를 먼저 보고 같은 상태에서 새 기준/이전 기준을 그룹으로 나눈 뒤 각 그룹 내 점수와 날짜를 사용한다. 100점과 15점을 하나의 숫자 척도로 직접 비교하지 않는다.

## 검증

- pytest 196 통과, 기존 Starlette/httpx 경고 1개.
- 프론트엔드 Node 41 통과, Vite 빌드 통과.
- 실제 FastAPI/Vite/Chromium의 새 시나리오 통과: 5항목 0점, 일시 불편 1점, 4/5 부분 확인, 119 possible/구급차 confirmed의 안내·진행 중지·중단 후 조회, 결과 상태 유지.
- 의도적 HTTP 500 저장 실패를 주입해 원문 보존·재시도·저장을 확인했다. 해당 오류를 정상 성공으로 숨기지 않았다.
- 최초 기존 테스트 5건은 옛 가중치/100점 기대값과 새 추가 질문 흐름 때문에 실패했다. 옛 점수 검사는 이전 통화 재생으로 명시하고 새 긴급 상태 검사를 분리한 뒤 전체 통과했다.
- 이전 전체 34개 브라우저 묶음은 이번 새 점수/추가 질문 기준으로 전체 재실행한 결과가 아니다. 이번 브라우저 결과는 전용 review_e2e.py 범위다.

실제 마이크 한국어 STT·TTS/벨소리 청감과 Windows 직접 실행은 미검증이다. 브라우저 음성 완료 이벤트는 제어된 모의 이벤트다. 규칙이 모든 사투리·복잡한 인용/부정·주체·지속 기간을 이해한다고 주장하지 않는다. 현재 정도 단서는 정해진 표현에 제한되며 불명확하면 점수를 비운다. 음성 오류의 서버 로그 저장은 네트워크 연결이 필요하다. API 장애 중 긴급 단서 입력에는 화면·음성으로 조건부 안전 안내를 제공하며, 서버에 기록되지 않은 내용을 저장 성공으로 표시하지 않는다.
