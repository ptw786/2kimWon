## 구현과 호환

기존 calls/turns/turn_attempts 및 API 경로를 유지했다. hybrid_state/hybrid_events를 추가하고 기존 통화에서 hybrid로 전환할 때 이전 확정 답변을 상태에 가져온다. 기본 UI는 hybrid를 사용하고 기존 API 소비자의 생략 요청은 legacy를 유지한다. DB 시작 백업과 기존 요청 키·순번·원자 저장을 유지한다.

규칙 모듈: normalizer.py, intent_classifier.py, entity_extractor.py, risk_detector.py, dialogue_manager.py, response_generator.py, scenarios.py. 분석 결과와 원문 근거를 분리하고, 대화 상태와 분석 이력을 SQLite에 보존한다. STT·TTS 구현은 재사용한다.

## 범위와 한계

새 테스트는 요청한 30개 이상 발화 사례, 위험 부정·과거·인용·복합 위험, 현재 질문별 응/아니, 복수 정보, 정정, 확인 한도, STT 실패/침묵 출처, 빈 답변 거부, 실제 API 저장·중복 재시도·중단·완료·DB 재시작 복원·서버 오류 롤백·복구·대시보드 및 기존 통화의 업그레이드를 포함한다.

음성 성공/권한 오류/TTS 순서는 모의 이벤트로 검사한다. native Chromium에서 API를 시도했지만 마이크 0개·한국어 음성 0개이므로 실제 한국어 인식·TTS 청감·벨소리 청감은 미검증이다. 사용자 PC/Windows 실행도 직접 검증하지 않았다.

자유 대화는 주제 단서와 한도에 따른 짧은 경청으로 제한된다. 모든 자연어·사투리·인용·복잡한 부정이나 시점 관계를 이해하지 않는다. 분류 실패는 재질문/unknown으로 보존한다. 생성형 모델, 실제 전화망, 자동 신고, 진단, 임상 평가, 자동 안전 해제는 구현하지 않았다. UI의 인식 오류는 안내 후 텍스트로 전환하며 자동으로 발화를 만들어 서버에 저장하지 않는다. 명시적 source=stt_error/silence API 이벤트는 별도 분류 가능하다.

GitHub 업로드는 이번 작업에 포함하지 않았다. 로컬 파일과 제공 ZIP이 이번 수정본이다.
