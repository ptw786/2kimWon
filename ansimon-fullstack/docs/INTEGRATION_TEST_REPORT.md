## 실제 확인한 회귀 범위

- 기존 대시보드·어르신 목록·혼합형 대화·STT/TTS 제어·벨소리 자원 정리·잘못된 ID·화면 이동.
- 빈 답변·IME·중복 제출·답변 저장 실패·응답 유실·시간 초과·서버 종료/복구·입력 보존.
- 5문항 완료·거절·중단·새로고침·서버 재시작 후 기존 기록 유지.
- 스케줄 시간/대상 검증, 한국 시간 경계, 놓친 최근 회차 복구, 다중 워커 중복 방지, 같은 회차의 경쟁 수신/거절.
- 수신과 예약 연결의 원자 저장·롤백·요청 키 재시도·예약 통화 복원·완료/중단 후 대기 제거.
- 예약 변경/해제 시 기존 완료 기록 보존, 진행 중 수정/해제 거부, 별칭 대상 연결 시 원래 대기 회차 유지.
- 점수와 판정의 일관성: 식사 12 + 수면 8 = 20, 모두 긍정/중립 0, 피로 9, 식사 정정 12, 이중 부정/복약 불필요 0, 위험 일시정지 100.
- `기분은 괜찮아요`가 건강 상태를 덮어쓰지 않음. 가족 발화·과거 시점·긍정의 부정을 추가 검증.
- 이전 taewon 기록의 출처·원본 요약·원점수·상세를 통합 React에서 조회, 새로고침 후 유지.

## DB 보존

실제 원본은 읽기 전용으로 접근하고 SQLite backup API로 스냅샷을 보관했다. 실제 원본에서 확인한 테이블별 수는 schedules 1, queue 1, records 5, elder_care_statistics 17, elderly_single_household_statistics 257, statistics_source_metadata 1이다. 통계/메타데이터까지 282행을 legacy_archive로 보존했다. 원본과 별도인 검증 DB에 가져왔으며 사용자 PC의 DB는 수정하지 않았다. 테스트는 전용 임시 DB만 사용한다. 실제 DB는 배포물과 새 GitHub 변경에서 제외한다.

## 미검증 및 제한

- native Chromium에서 음성 API를 시도했지만 입력 장치와 한국어 음성은 각각 0개였다. 실마이크 한국어 STT, TTS/벨소리 청감, 실제 Windows 실행은 미검증이다. 음성 정상·오류·완료 제어 자동 검사는 모의 이벤트를 사용한다.
- 예약은 웹 시연 대기열이며 실제 전화 발신이나 자동 신고가 아니다.
- 원본 통계는 행 보존만 제공하며 별도 통계 화면을 새로 만들지 않았다. 원본의 전체 기록 삭제는 자동 이식하지 않았다.
- 우선순위는 시연 규칙이며 의료 진단이 아니다. 이전 기록 원점수는 보존하며 과거 기록을 임의 재평가하지 않는다.
- 조회 개수는 기존 최대 500개 정책이며 페이지네이션은 추가하지 않았다. 대규모 기록의 점수 계산 성능은 별도 부하 검증이 필요하다.
