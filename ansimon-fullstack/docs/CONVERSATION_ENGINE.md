# 안심온 규칙 기반 대화 엔진

2026-11-09. React + FastAPI + SQLite 및 기존 화면·벨소리·HTTP 500 수정 사항을 유지했다. OpenAI API, LLM, 유료 외부 API를 호출하지 않는다. 질문·분류·응답·요약은 로컬 Python 규칙으로 처리한다.

## 시나리오

1. 건강 상태: “안녕하세요, 안심온입니다. 오늘 몸은 좀 어떠세요?”
2. 식사: “오늘 식사는 잘 챙겨 드셨나요?”
3. 수면: “어젯밤 잠은 편히 주무셨나요?”
4. 복약: “드시는 약은 잘 챙겨 드셨나요?”
5. 기분: “오늘 기분은 어떠세요? 불편한 곳은 없으세요?”

새 답변은 네 가지 코드와 한글 라벨로 분류한다: `positive`(긍정), `negative`(부정), `neutral`(중립), `unknown`(확인 불가).

| 질문 | 답변 예 | 분류·후속 응답 |
|---|---|---|
| 건강 | 안 아파 | 긍정. 몸이 괜찮으시다니 다행이에요. |
| 건강 | 많이 아파 | 부정. 몸이 불편하시군요. 증상이 심하거나 계속되면 도움을 요청해 주세요. |
| 식사 | 밥 먹었어 | 긍정. 식사를 챙겨 드셨군요. 알려주셔서 감사합니다. |
| 식사 | 밥 안 먹었어 | 부정. 아직 식사를 못 하셨군요. 식사를 챙기실 수 있으면 좋겠어요. |
| 수면 | 잘 잤어 | 긍정. 편히 주무셨다니 다행이에요. |
| 수면 | 잠을 못 잤어 | 부정. 잠을 편히 못 주무셨군요. 불편함이 계속되면 도움을 요청해 주세요. |
| 복약 | 약 먹었어 | 긍정. 약을 챙겨 드셨군요. 알려주셔서 감사합니다. |
| 복약 | 먹는 약 없어 | 중립. 드시는 약이 없으시군요. 알려주셔서 감사합니다. |
| 기분 | 기분 좋아 | 긍정. 기분이 좋으시다니 다행이에요. |
| 기분 | 외로워 | 부정. 마음이나 몸이 편치 않으시군요. 가까운 분이나 담당 생활지원사에게 말씀해 주세요. |
| 공통 | 의미 없는 답변 | 확인 불가. 최대 두 번 재질문 후에도 불명확하면 확인 불가로 확정. |
| 공통 | 빈 문자열·공백 | HTTP 422. 저장·재질문 횟수 소모 없음. |

단순히 ‘안’이라는 글자를 찾지 않는다. 질문별 행동·증상 표현을 구분하고 부정된 증상을 먼저 마스킹한다. ‘안 아파’는 건강 긍정이며 ‘안 아픈데 어지러워’는 부정이다. 식사 중 ‘약 먹었어’, 복약 중 ‘밥 먹었어’처럼 명시적으로 다른 항목을 대답하면 다시 확인한다. 이중 부정 등 불명확한 식사 답변은 추측하지 않는다. 정해진 규칙에 없는 표현은 확인 불가로 처리한다.

## 저장·재질문·중복 방지

`POST /api/calls/{id}/turns`에 `{answer,index,attempt}`를 전송한다. index는 0~4, attempt는 최초 0, 재답변 1, 2다.

- 최초 불명확 답변: 답변 시도를 저장하고 같은 질문으로 첫 재질문. 확정 문항 수 `count`는 증가하지 않는다.
- 첫 재답변도 불명확: 두 번째 재질문. count는 유지한다.
- 두 번째 재답변도 불명확: 해당 문항을 unknown으로 확정하고 다음 질문으로 이동한다. 총 세 번의 답변 기회다.
- 재답변에서 명확한 답변이 오면 즉시 해당 분류로 확정한다.
- 서버의 BEGIN IMMEDIATE 트랜잭션 안에서 답변 시도·분류·후속 응답·확정 문항을 원자적으로 저장한다. 저장 오류 시 둘 다 롤백한다.
- `(call_id, question_index, attempt)` 유니크 제약으로 동일 시도의 중복 저장을 막는다. 같은 순번·같은 답변 재전송은 저장된 JSON 응답을 그대로 반환한다. 다른 답변·잘못된 순서는 409로 거절한다. 선택 Idempotency-Key도 지원한다.
- 프론트엔드는 index와 attempt를 항상 보낸다. 구형 클라이언트의 생략 요청도 받을 수 있지만, 응답 유실 시 정확한 재전송 식별에는 명시적 순번이 필요하다.
- 응답에는 기존 count/reply/finished/next_question 외에 classification, classification_label, needs_retry, retry_count, next_attempt, emergency를 포함한다.
- 통화 상세에는 최종 `turns`, 전체 `attempts`, 복원용 `dialogue_state`를 반환한다. 재질문 횟수는 서버·브라우저 재시작 후에도 유지한다.

기존 turns 테이블에는 classification/reply/emergency 열만 추가하고 `turn_attempts` 테이블을 새로 만든다. 기존 DB가 있으면 변경 전 SQLite backup API로 백업한다. 기존 통화·답변·요약을 삭제하거나 재작성하지 않는다. 과거 답변은 `unclassified`(기존 답변·미분류)로 보존하고 이번 엔진이 분류했다고 표시하지 않는다. 새 답변의 분류 네 가지와 구분하기 위한 과거 데이터 표식이다.

## React 연동과 음성 순서

1. 서버의 현재 질문을 표시하고 브라우저 TTS로 읽는다.
2. 읽기가 끝나면 STT 또는 텍스트 답변을 받는다.
3. 원문·질문 순번·답변 시도 순번을 FastAPI에 보낸다.
4. 서버 저장 성공 응답 후 사용자 답변과 분류·후속 응답을 표시한다.
5. 후속 응답의 TTS 완료 이벤트 뒤에 다음 질문을 표시하고 읽는다. 재질문이면 같은 질문을 다시 읽는다.
6. 다섯 문항이 확정되면 마지막 후속 응답과 인사말을 읽은 뒤 finish API로 완료한다.

네트워크 오류 시 텍스트·STT 원문과 전송 순번을 현재 화면에 보존하고 ‘다시 시도’로 동일 요청을 재전송한다. 저장 여부가 확인되기 전에는 새 입력을 잠가 불확실한 답변을 덮어쓰지 않는다. 응답 유실 후 재시도해도 재질문 횟수나 확정 문항이 중복 증가하지 않는다. 아직 서버에 저장되지 않은 입력은 브라우저 새로고침까지 영구 보존하는 기능을 추가하지 않았다.

TTS 중에도 통화 종료 버튼은 사용할 수 있다. 종료하면 음성을 취소하고 대화 진행 작업을 무효화하며 이미 커밋된 답변은 유지한다. 화면 이탈 시 요청·타이머·TTS·STT를 정리한다. 음성 미지원·재생 오류·완료 이벤트 지연 시 안내를 표시하고 텍스트로 진행한다. TTS에 실패해도 DB 저장을 성공으로 위장하지 않는다.

## 요약 및 긴급 표현

요약에는 최종 분류가 positive/negative/neutral인 문항의 **실제 저장 답변**만 원문으로 연결한다. unknown의 무의미한 원문·재질문 중 미확정 답변·과거 미분류 답변은 새 요약의 확인 내용에 넣지 않는다. unknown 항목 이름은 ‘확인 불가 항목’으로 구분한다. 약을 먹지 않는다고 해서 복약 완료로 만들거나, 몸이 아프다고 질환명을 생성하지 않는다.

‘숨을 못 쉬겠어’, ‘가슴이 너무 아파’, ‘쓰러졌어’, ‘죽고 싶어’ 등 명시적 긴급 표현은 질문에 관계없이 직접 119 또는 가까운 사람에게 도움을 요청하도록 안내한다. 화면·응답에 **‘안심온은 실제 119 신고를 하지 않습니다’**를 표시한다. 실제 신고 기능·신고 완료 표시는 없다. 요약에는 안내문 생성과 자동 신고 없음만 기록한다. ‘호흡 곤란이 없어요’ 등 부정된 긴급 표현은 별도로 제외한다.

## 자동 검증

- 백엔드 pytest **70개 통과**. 요청한 최소 12문장 전부 포함. 질문별 부정·중립·다른 주제·무의미·긴급/부정된 긴급 표현, 두 번 재질문, 동시·유실 재전송, DB 롤백, 기존 DB 백업·마이그레이션, 별도 프로세스 재시작을 검증했다.
- 실제 Uvicorn + Vite + Chromium **18개 시나리오 묶음 통과**. 기존 화면/벨소리 회귀 12개와 대화 연동 6개를 검증했다.
- 대화 연동은 실제 HTTP/SQLite를 사용했다. TTS 완료/오류와 STT 인식 결과 이벤트는 테스트에서 제어해 후속 응답→다음 질문, 마지막 TTS→통화 종료 순서를 검증했다. 스피커 청감이나 실제 마이크 정확도를 검증했다고 주장하지 않는다. 서버 500·응답 유실도 명시적으로 주입했다.
- `npm run build` **통과**. 기존 프레임워크와 의존성을 유지했다.
- pytest에 기존 Starlette/httpx deprecation warning 1개가 있다.

실행: 기존과 동일하게 backend에서 uvicorn main:app, frontend에서 npm run dev. 전체 테스트는 프로젝트 루트에서 `.venv/bin/python -m pytest -q backend/tests`, `python frontend/tests/e2e.py`, frontend에서 `npm run build`로 실행한다. Windows Python 경로는 README의 가상환경 안내를 따른다.

규칙 엔진은 범용 한국어 이해 모델이 아니다. 표현·이중 부정·문맥이 규칙을 벗어나면 재확인이 필요하다. 실제 마이크·한국어 음성·Safari/Firefox 기기 검증은 별도다. 브라우저 STT는 기존처럼 브라우저 제공 서비스에 의존할 수 있으며, 대화 분류·요약 자체는 외부 API를 사용하지 않는다.
