## F1 안부전화 발신
- **무엇:** 어르신마다 정한 시간에 벨이 울린다. 30초 안 받으면 `미응답`, 10분 뒤 한 번 더 건다(하루 최대 2회). 생활지원사가 웹에서 바로 걸 수도 있다. 거절하면 `수신 거절`.
- **수용 기준:** 통화 시각부터 2시간 안에만 자동 발신 · 미응답과 '아직 안 건 것'이 구분됨 · 같은 어르신에게 벨이 겹치지 않음(409).
- **코드:** `apps/api/app/calls.py` `create_call` `scheduler_tick` `apply_timeouts` `decline_call` · `routers/staff.py` `POST /staff/residents/{id}/call` · 앱 `features/call` 벨 화면 · 웹 '전화 걸기' 버튼
- **테스트:** `apps/api/tests/test_api.py` (발신·409·미응답·재시도·하루 2회)

## F2 음성 대화
- **무엇:** AI가 질문을 읽고(TTS), 말이 끝나면 자동으로 듣는다(STT). 말 대신 큰 선택 버튼이나 글자로도 답할 수 있다. 10초 동안 말이 없으면 무응답으로 보낸다. 마이크가 없어도 통화를 끝까지 할 수 있다.
- **수용 기준:** TTS와 STT가 동시에 켜지지 않음 · 마이크 거부/미지원 시 버튼·글자로 완료 · 새로고침해도 통화 이어감.
- **코드:** 앱 `features/call/speech/{recognition,synthesis}.ts` `features/call/CallContext.tsx` · API `POST /elder/calls/{id}/turn`
- **테스트:** `apps/app/tests/speech.test.ts` · 가짜 음성 통화 시나리오 `apps/app/scripts/fake_speech.js`

## F3 맥락 추가 질문 (AI 에이전트)
- **무엇:** 답변에서 항목과 상태를 뽑고(Ollama `ax4-light`, 인용 필수), 다음 행동은 코드가 정한다 — 다음 질문 / 같은 질문 다시 / 구체적으로 다시 묻기(최대 2회 뒤 '미확인'). 공감 한 문장은 AI가, 질문 원문은 코드가 붙인다. AI가 4초 안에 답하지 못하면 키워드 규칙이 대신한다.
- **수용 기준:** "뭐라고요?"는 진행하지 않음 · 인용이 답변에 없으면 버림 · AI 실패 시에도 통화가 끊기지 않음 · 모든 AI 호출을 `ai_runs`에 기록.
- **제안서와 다른 점 (결정 필요):**
  1. ~~'미식사'와 '식사 어려움' 구분 없음~~ → **r2.1에서 해결**: 항목 상태와 별도로 `어려움 유형`(식사 어려움 · 수면 문제 · 도움 요청 · 외로움, `domain/needs.py`)을 찾고, 이유 없이 못 먹었다고 하면 제안서 문장으로 한 번 다시 묻는다(판정규칙.md §8).
  2. 제안서 3.가는 "규칙 기반 발화 분석"이라고 썼다. 현재는 **Ollama LLM + 규칙 대체**다. 제안서 문구를 고치거나 LLM을 끄고 규칙만 쓰거나 정해야 한다.
- **코드:** `apps/api/app/domain/{dialogue,keywords,needs,questions,textutil}.py` · `services/llm.py` · `services/prompts/*.md` · `calls.py` `process_turn`
- **테스트:** `test_regressions.py`(이전 버그 5개) · `test_llm_fallback.py` · `test_rules.py`(짧은 대답·부정 표현) · `test_needs.py`(어려움 유형·식사 재질문)

## F4 도움 요청 → 즉시 확인
- **무엇:** "도와줘", "119", "넘어졌어", "숨이 차" 같은 표현은 점수와 상관없이 바로 최상위 단계로 올리고, 통화 중 고정 안내를 한다. **규칙(정규식)으로만** 판단하며 AI가 끄지 못한다.
- **코드:** `apps/api/app/domain/safety.py` · `rules.yaml`
- **테스트:** `test_rules.py` 안전 신호 16가지 · `test_llm_fallback.py`(AI가 '양호'라 해도 긴급 유지)

## F5 확인 우선순위와 판단 근거
- **무엇:** 오늘 통화(최대 50) + 최근 7일 추세(최대 30) + 연락 상태(최대 20) = 100점. 모든 점수에 이유와 어르신 말씀 인용을 붙인다. 나이·성별은 쓰지 않는다.
- **단계 이름 (2026-11-14 결정):** 팀원 review-v2 용어로 통일 — **즉시 확인**(안전 표현, 점수와 별개) / **우선 확인** / **추가 확인** / **특이 표현 없음**. 키(urgent·today·watch·ok)는 그대로, 라벨은 `rules.yaml` 한 곳. 제안서 3.나.3의 '식사 어려움 → 추가 확인'은 '우선 확인'으로 고칠지 제안서 작업 때 정한다.
- **코드:** `apps/api/app/domain/scoring.py` · `rules.yaml`
- **테스트:** `test_rules.py`(표 한 줄 = 테스트 하나) · `test_rules_sensitivity.py` → `docs/평가/`

## F11 복지서비스 연계 (서버 구현됨)
- **무엇(제안서 4·6.나):** 통화에서 확인한 생활 어려움 + 거주 지역으로 한국사회보장정보원 **지자체복지서비스** · **사회복지시설** 데이터를 조회해 급식·도시락 지원사업 등을 생활지원사에게 보여 준다.
- **왜 중요한가:** 심사 '사회보장 데이터 활용' 25점. 지금 제안서의 데이터 활용은 KOSIS 독거노인가구비율(대상 규모 파악)뿐이다.
- **지금:** 한국사회보장정보원 지자체복지서비스(15108347)·중앙부처복지서비스(15090532)에서 어르신 대상 + 어려움 낱말 일치 21건을 골라 `apps/api/app/data/welfare_subset.json`(수집일 2026-11-13, 오프라인)에 둔다. 같은 시군구 → 시도 → 중앙부처 순 최대 3건, 노인맞춤돌봄서비스는 뺌. 관심주제 태그는 품질이 낮아 쓰지 않는다(`app/data/README.md`). 사회복지시설 데이터는 아직 없다.
- **API:** `GET /staff/residents/{id}`(최근 7일 어려움) · `GET /staff/calls/{id}`(그 통화 어려움)의 `welfare: WelfareMatch[]`, 어르신 `region`
- **코드:** `apps/api/scripts/build_welfare_subset.py` · `services/welfare.py`(어댑터) · `domain/matching.py` · `rules.yaml` `welfare` · 웹 상세 패널 '연계할 만한 지원'
- **테스트:** `apps/api/tests/test_welfare.py`
