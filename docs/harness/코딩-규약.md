# 안심온 코딩 규약

짧게, 지키기 쉽게. 리뷰에서 지적할 수 있을 만큼 구체적으로. 예외는 코드 주석에 이유를 쓴다.

## 1. 함수
- **두 번 쓰면 함수다.** 복사해서 조금 바꾼 코드는 반려.
- **함수는 한 가지 일.** 이름이 "그리고"로 설명되면 둘로 나눈다.
- **순수 함수 먼저.** 입력만으로 출력이 정해지면 `domain/`에. 시각이 필요하면 `now`를 인자로.
- **이름은 동사.** 불리언은 `is_` `has_` `should_`.
- **인자 4개 초과 → 구조로 묶기.** Python `dataclass(frozen=True)`, TS 객체 하나.
- **타입.** Python은 모든 인자·반환에 타입 힌트. TS는 `strict`, `any` 금지(`unknown` 후 좁히기).
- **길이.** 함수 40줄, 파일 400줄을 넘으면 나눌 이유를 찾는다.

## 2. 튜플·인덱스
- 자리 뜻이 있는 묶음은 **2개까지만** 튜플(언패킹해서 쓴다). 3개 이상은 `NamedTuple`/`dataclass`, TS는 객체.
- `x[0]`, `x[1]` 대신 언패킹. 순회 위치는 `enumerate`, 변수 이름은 `turn_idx`처럼 뜻이 보이게.
- 사전은 `.get(key)` + 없을 때 동작을 정한다.

## 3. 판정 규칙
- 점수·기준선·라벨은 `rules.yaml`에만. 코드에 숫자를 직접 쓰지 않는다.
- 규칙을 바꾸면: `rules.yaml` → `판정규칙.md` → `rule_version` → 테스트 → `docs/평가/` 민감도 다시 실행.
- 나이·성별·주소는 점수 함수의 인자로 받지 않는다(받을 수 없게 시그니처로 막는다).
- AI 결과는 **인용이 답변 안에 있을 때만** 쓴다. 안전 신호는 규칙으로만.

## 4. LLM
- 호출은 `services/llm.py`로만. 프롬프트 원문은 `services/prompts/*.md` 파일로.
- 구조화 출력(JSON 스키마) + 검증 실패·시간 초과 시 규칙으로 대체. 모든 시도를 `ai_runs`에 남긴다.
- DB 쓰기 트랜잭션 안에서 부르지 않는다.
- 어르신 발화 원문은 서버 로그에 남기지 않는다(DB에만).

## 5. 화면
- 색·글꼴·간격은 `packages/design/tokens.css` 변수만. 색 코드를 직접 쓰지 않는다.
- **카드·인용·표 행에 왼쪽 색 선 금지.** 강조는 배경·전체 테두리·배지로.
- 글자 최소: 웹 16px, 앱 20px. 상태는 아이콘 + 한글 라벨(색만 쓰지 않음). 빨강은 긴급에만.
- 상태 라벨·아이콘은 `shared/status.ts` 한 곳. 사용자 문구는 해요체.
- 새 화면은 1440·390(앱은 390·330) 스크린샷을 찍어 시안과 비교한 뒤 올린다.
- 빈 상태·로딩·오류 상태를 반드시 만든다.

## 6. 테스트
- domain 함수는 판정규칙 표 한 줄 = 테스트 하나.
- 버그를 고치면 먼저 재현 테스트를 쓴다(`test_regressions.py`).
- 테스트는 `ANSIMON_LLM=off`, 임시 DB로 돌린다. 실제 Ollama 확인은 스모크로 따로.

## 7. Git
- 브랜치 `feat/F<번호>-설명`, `fix/F<번호>-설명`. 기능 ID는 [기능-명세.md](기능-명세.md).
- 커밋 첫 줄은 한국어, `[F3] 식사 어려움 재질문 추가` 형식.
- `.env`, `*.db`, `node_modules`, `.omc/`, `.venv`는 올리지 않는다.
- 계약(`CONTRACT.md`)을 바꾸는 커밋에는 서버·웹·앱 수정을 같이 넣는다.
