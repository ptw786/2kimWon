## 1. 원칙

1. **AI는 확인 대상을 늘리는 쪽으로만 쓴다.** AI가 '괜찮다'고 해도 규칙이 잡은 위험 신호를 내리지 않는다.
2. **점수는 코드가 계산한다.** AI는 "어느 항목이, 어떤 상태인지, 근거 문장"만 낸다.
3. **모르는 건 모른다고 쓴다.** 답을 못 들은 항목은 `미확인`(0점)으로 두고 '확인 필요' 표시를 붙인다. 추측으로 채우지 않는다.
4. **나이·성별은 점수에 넣지 않는다.** 같은 말을 했으면 같은 점수다.
5. **진단이 아니다.** 결과는 생활지원사가 누구부터 볼지 정하는 순서일 뿐이며, 의료 판단·자동 신고를 하지 않는다.

## 2. 항목별 상태 (매 통화)

다섯 항목(몸 상태·식사·수면·복약·기분)마다 아래 넷 중 하나로 판정한다.

| 상태 | 뜻 | 예시 답변 |
|---|---|---|
| 양호 | 문제 표현 없음 | "밥 잘 먹었어", "약 없어"(복약 대상 아님도 양호) |
| 주의 | 일상 불편 | "좀 피곤해", "입맛이 없어 아침 걸렀어", "잠을 설쳤어" |
| 위험 | 이어지면 건강에 영향 · 오늘 안에 확인 | "이틀째 못 먹었어", "약을 며칠 안 먹었어", "어지러워", "넘어졌어", "식은땀이 나", "아무도 안 와서 외로워" |
| 미확인 | 답을 못 들음·관련 없는 답 | 무응답, 두 번 다시 물어도 알아듣기 어려움 |

## 3. 안전 신호 → 바로 '즉시 확인'

아래 표현이 나오면 점수와 상관없이 **즉시 확인**이다. 통화 중에 바로 생활지원사 화면(대시보드 맨 위·알림 막대·소리)에 뜨고, 어르신께는 고정 안내("생활지원사님 화면에 바로 알렸어요. 위급하시면 지금 119에 전화하세요.")를 한다. 자해·삶의 의지면 "109(자살예방 상담전화)" 안내를 덧붙인다. 이 판단은 **규칙(정규식, `domain/safety.py`)으로만** 하며 AI가 끄지 못한다. 문자·전화 자동 발송과 119 자동 신고는 하지 않는다.

| 분류 | 예 (어르신 말투) | 근거 (§9) |
|---|---|---|
| 호흡·가슴 | 숨이 차, 숨이 안 쉬어져, 숨을 쉴 수가 없어, 가슴에 통증이 있어, 가슴이 쥐어짜듯·짓누르듯 아파, 가슴이 꽉 막혀 · **식은땀 + 가슴·숨·떨림·어지럼·체한 느낌** | 응급증상 "급성 호흡곤란", "심장질환으로 인한 급성 흉통" · 질병관리청 심근경색 조기증상 [S1][S2][S3] |
| 뇌졸중 의심 | 입이 돌아갔어, 얼굴 한쪽이 마비, 말이 어눌해, 말이 안 나와, 혀가 꼬여, 한쪽 팔·다리에 힘이 없어, 갑자기 앞이 안 보여, 한쪽 눈이 안 보여, 물건이 두 개로 보여, 머리가 깨질 듯 아파, 어지러워서 서 있을 수가 없어 | 대한뇌졸중학회 '이웃손발시선' · 질병관리청 뇌졸중 조기증상 · 응급증상 "급성 신경학적 이상", "급성 시력소실" [S2][S4] |
| 의식 | 정신을 잃었어, 쓰러졌었어, 기절했어, 정신이 가물가물해, 경련 | 응급증상 "급성 의식장애" [S1] |
| 낙상 | 넘어져서 못 일어나, 일어날 수가 없어, 머리를 부딪혔어 · **넘어짐 + 많이 아픔·구토·피·어지럼** | 건보공단 "일어날 수 없을 정도로 통증이 심하면 … 119" · 응급증상 "구토·의식장애 등이 있는 두부손상" [S5][S1] |
| 출혈·화상·중독 | 피가 안 멈춰, 피를 토했어, 까만 변을 봤어, 크게 데었어, 약을 한꺼번에 먹었어 | 응급증상 "지혈이 안 되는 출혈", "화상", "약물 과다 복용·중독" [S1] |
| 화재·가스 | 불이 났어, 연기가 자욱해, 가스 냄새가 나 | 응급안전안심서비스 화재 감지 → 119 연계 [S8] |
| 자해·삶의 의지 | 죽고 싶어, 살기 싫어, 살아서 뭐해, 살 이유가 없어, 사라지고 싶어, 나 같은 거 없어져야 해, 짐만 돼, 따라가고 싶어 | 복지부 "죽고싶다" 언어 경고신호 · 심리부검 "죽음 언급 63.6%, 자기비하 47.0%" · 응급증상 "자신을 해할 우려" [S6][S7][S1] |
| 도움 요청 | 119, 살려줘, 도와줘, 구급차, 응급실, 사람 좀 보내줘 | 응급호출 취지 (서비스 정책) |

- **넘어짐·식은땀 단독은 몸 상태 '위험'**(→ 우선 확인, 오늘 안에 연락)이다. 근거가 "못 일어남·머리 부딪힘·구토"를 119 기준으로 들고 있어, 한 단계 아래로 둔다. 둘이 같은 답에 같이 나오면 안전 신호다.
- 일이 있었다는 말("어제 넘어져서 못 일어났는데 지금은 괜찮아")은 **걸러내지 않는다**(놓치는 것보다 한 번 더 보는 쪽).
- 바로 뒤에 분명한 부정이 붙은 말("숨 차는 건 없어", "가슴 아픈 데는 없어요", "넘어진 적은 없어")과 관용구("정신이 없어(=바빠)", "힘들어 죽겠어", "배고파 죽겠네")는 안전 신호가 아니다.
- 몸과 관련된 안전 신호(호흡·가슴·뇌졸중·의식·낙상·출혈)는 몸 상태도 '위험'으로 기록한다(몸 상태가 '미확인'으로 남지 않게).

## 4. 확인 점수 (0~100)

점수 = **A 오늘 통화** + **B 최근 추세** + **C 연락 상태**

| 구분 | 계산 | 최대 |
|---|---|---:|
| A 오늘 통화 | 항목마다 주의 5점, 위험 10점 (5항목) | 50 |
| B 최근 추세 | 같은 항목이 주의 이상으로 **2일 연속** +5, **3일 이상 연속** +10 (항목별, 합계 상한 30) | 30 |
| C 연락 상태 | 오늘 미응답 1회 +10, **연속 2회 이상** +20 / 통화 중단(답변 일부만) +5 / 수신 거절 +5 | 20 |

## 5. 단계 (r3: 단계는 사실로, 점수는 순서로)

r2.1까지는 점수만으로 단계를 정해서 **"많이 아파요"(몸 위험, 10점)가 '특이 표현 없음'**으로 나오는 모순이 있었다(외부 리뷰 #5). r3은 들은 사실로 단계를 정하고, 점수는 같은 단계 안에서 누구를 먼저 볼지에만 쓴다. 그래서 '특이 표현 없음'이면 이유 목록이 비어 있다.

| 단계 (키) | 조건 (위에서부터 먼저 맞는 것) | 생활지원사에게 |
|---|---|---|
| 즉시 확인 (`urgent`) | 안전 신호 1개 이상 (§3) | 지금 바로 연락 |
| 우선 확인 (`today`) | 위험 항목 1개 이상 · **연속 미응답 2회 이상**(이번 통화 포함) · 40점 이상 | 오늘 안에 전화·방문 |
| 추가 확인 (`watch`) | 주의 항목 · 추세 · 연락 문제(미응답·중단·거절·받았지만 대답 없음) · 어려움 유형(§8) 중 하나라도 · 미확인 2개 이상 | 다음 통화 때 다시 보기 |
| 특이 표현 없음 (`ok`) | 위 어느 것도 없음 | 기록만 |

- 판정마다 `grade_basis`(이 단계인 이유 한 줄: '위험 항목 (몸 상태)', '연속 미응답 2회' 등)를 같이 저장해 화면에 보인다.
- **연속 미응답 2회**: 스케줄러가 하루 최대 2번(정한 시각, 10분 뒤 한 번 더) 걸기 때문에, 2회 연속 미응답 = 그날 연락이 닿지 않음이다. 노인맞춤돌봄 현장도 "전화 연락이 닿지 않는 어르신은 생활지원사가 직접 방문"한다 [S9]. 횟수(2)는 공식 기준이 아니라 이 서비스가 정한 값이다.
- **하루 대표 판정**: 같은 날 통화가 여럿이면 대시보드는 **가장 심한 판정**을 보인다(같은 단계면 확인 기록이 없는 것 → 점수 높은 것 → 최근 것). 안전 신호가 나온 뒤 다시 건 전화를 거절해도 '즉시 확인'은 내려가지 않는다(외부 리뷰 #3). 확인 기록은 그 판정을 만든 통화의 것만 붙는다(#4).
- 다섯 질문 동안 한마디도 듣지 못하면 '통화 완료'가 아니라 '통화 중단'이고, '받았지만 대답 없음'(+10, 미응답과 같은 무게)이 붙는다.

r2까지의 라벨(긴급 · 오늘 확인 · 관찰 · 양호)을 제안서 용어(즉시 확인 · 추가 확인)에 맞춰 바꿨다. '양호'는 "문제가 없다"고 단정하는 말이라 **'특이 표현 없음'**(통화에서 걱정할 표현을 듣지 못함)으로 바꿨다. 항목 상태의 '양호'(§2)는 그대로다.

## 6. 이유 표시 형식

```
우선 확인 · 45점
· 식사 위험 (10)  "이틀째 밥을 못 먹었어"
· 식사 3일 연속 (+10)
· 수면 주의 (5)   "잠을 좀 설쳤지"
· 어제 미응답 (+10)
어려움: 식사 어려움 "혼자 차려 먹기가 힘들어서 그래"   ← 점수와 별개 (§8)
```

## 7. 이 값들은 가설이다

가중치와 기준선은 현장 검증 전 **시연용 가설**이다. 대신 `apps/api/tests/test_rules_sensitivity.py`에서 점수 하나씩 ±5로 바꿔도 상위 순위가 크게 흔들리지 않는지 확인하고, 그 결과를 `docs/평가/`에 남긴다.

## 8. 어려움 유형 (r2.1, 점수와 별개)

항목 상태가 "무엇이 얼마나 나쁜가"라면, 어려움 유형은 **"지원이 필요할 수 있는 사정"**이다. 제안서 3.나.2의 구분 — "아직 밥을 안 먹었어요"(미식사)와 "먹을 게 없어서 밥을 못 먹었어요"(식사 어려움 → 지원 필요) — 을 여기서 한다.
점수에는 **넣지 않는다**(같은 '식사 주의'라도 점수는 같다). 다만 어려움이 있으면 '특이 표현 없음'이 될 수 없으므로 단계는 최소 **추가 확인**이다(r3). 생활지원사 화면의 '어려움'과 복지서비스 연계(F11)의 입력으로 쓴다.

| 유형 (키) | 예 | 아닌 것 |
|---|---|---|
| 식사 어려움 (`meal_difficulty`) | 먹을 게 없어, 반찬 살 돈이 없어, 혼자 차려 먹기 힘들어, 장 보기가 힘들어, 반찬이 없어 | 아직 안 먹었어, 입맛이 없어 |
| 수면 문제 (`sleep_problem`) | 며칠째 잠을 못 자, 잠이 안 와, 밤새 뒤척였어, 한숨도 못 잤어 | 잠을 좀 설쳤어(수면 주의만) |
| 도움 요청 (`help_request`) | 도움이 필요해, 도와줄 사람이 없어, 누가 좀 와 줬으면 | 119, 살려줘, 도와줘 → §3 안전 신호 |
| 외로움 (`loneliness`) | 외로워, 아무도 안 와, 말할 사람이 없어 | 안 외로워 |

- 규칙(`domain/needs.py`, 띄어쓰기·문장부호 무시)으로 먼저 찾고, AI가 찾은 것은 **인용이 답변 원문에 있을 때만** 더한다. 규칙이 찾은 것은 AI가 지우지 못한다.
- 한 통화의 어려움은 유형마다 처음 나온 인용 하나로 모은다(`Assessment.needs`). 어르신 상세의 복지 연계는 최근 7일 어려움을 쓴다.
- **식사 재질문**: 식사 질문에 '못/안 먹음'(주의·위험)이라고 했는데 식사 어려움도 이유("입맛이 없어서" 등)도 없으면, 한 번만 "아직 식사 전이신가요, 아니면 식사하기 어려운 이유가 있으신가요?"라고 묻는다. 큰 버튼은 '아직 식사 전이에요'(어려움 없음) · '먹을 게 없어서 못 먹었어요' · '혼자 차려 먹기 힘들어요'(식사 어려움). 다시 묻기 2회 한도에 들어가고, 이미 기록한 식사 상태는 내리지 않으며, 대답이 무엇이든 다음 질문으로 넘어간다.
