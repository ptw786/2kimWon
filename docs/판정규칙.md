> r2.1 (2026-11-14): 단계 **라벨만** 팀 용어로 바꿈(키·점수 계산은 r2 그대로) · §8 어려움 유형 추가(점수와 별개).

## 1. 원칙

1. **AI는 확인 대상을 늘리는 쪽으로만 쓴다.** AI가 '괜찮다'고 해도 규칙이 잡은 위험 신호를 내리지 않는다.
2. **점수는 코드가 계산한다.** AI는 "어느 항목이, 어떤 상태인지, 근거 문장"만 낸다.
3. **모르는 건 모른다고 쓴다.** 답을 못 들은 항목은 `미확인`(0점)으로 두고 '확인 필요' 표시를 붙인다. 추측으로 채우지 않는다.
4. **나이·성별은 점수에 넣지 않는다.** 같은 말을 했으면 같은 점수다.
5. **진단이 아니다.** 결과는 생활지원사가 누구부터 볼지 정하는 순서일 뿐이며, 의료 판단·자동 신고를 하지 않는다.

## 2. 항목별 상태 (매 통화)

다섯 항목(몸 상태·식사·수면·복약·기분)마다 아래 넷 중 하나로 판정한다.

| 상태 | 뜻 | 예시 답변 |
|---|---|---|
| 양호 | 문제 표현 없음 | "밥 잘 먹었어", "약 없어"(복약 대상 아님도 양호) |
| 주의 | 일상 불편 | "좀 피곤해", "입맛이 없어 아침 걸렀어", "잠을 설쳤어" |
| 위험 | 이어지면 건강에 영향 | "이틀째 못 먹었어", "약을 며칠 안 먹었어", "어지러워", "아무도 안 와서 외로워" |
| 미확인 | 답을 못 들음·관련 없는 답 | 무응답, 두 번 다시 물어도 알아듣기 어려움 |

## 3. 안전 신호 → 바로 '즉시 확인'

아래 표현이 나오면 점수와 상관없이 **즉시 확인**으로 표시하고, 통화 중 고정 안내("지금 바로 생활지원사님께 알려 드릴게요. 위급하시면 119에 전화하세요.")를 한다. 이 판단은 **규칙(정규식)으로만** 하며 AI가 끄지 못한다.

| 분류 | 예 |
|---|---|
| 낙상 | 넘어졌어, 쓰러졌어, 못 일어나 |
| 호흡·가슴 | 숨이 차, 숨을 못 쉬겠어, 가슴이 아파·답답해 |
| 의식·마비 | 정신이 없어, 말이 안 나와, 한쪽이 마비 |
| 자해·삶의 의지 | 죽고 싶어, 살기 싫어 |
| 도움 요청 | 119, 살려줘, 도와줘 |

부정·과거 표현("어제 넘어질 뻔했는데 괜찮아")은 규칙이 1차로 걸러도 **즉시 확인을 유지하고** 생활지원사가 판단한다(놓치는 것보다 한 번 더 보는 쪽을 택함).

## 4. 확인 점수 (0~100)

점수 = **A 오늘 통화** + **B 최근 추세** + **C 연락 상태**

| 구분 | 계산 | 최대 |
|---|---|---:|
| A 오늘 통화 | 항목마다 주의 5점, 위험 10점 (5항목) | 50 |
| B 최근 추세 | 같은 항목이 주의 이상으로 **2일 연속** +5, **3일 이상 연속** +10 (항목별, 합계 상한 30) | 30 |
| C 연락 상태 | 오늘 미응답 1회 +10, **연속 2회 이상** +20 / 통화 중단(답변 일부만) +5 / 수신 거절 +5 | 20 |

## 5. 단계

| 단계 (키) | 조건 | 생활지원사에게 |
|---|---|---|
| 즉시 확인 (`urgent`) | 안전 신호 1개 이상 | 지금 바로 연락 |
| 우선 확인 (`today`) | 40점 이상 **또는** 위험 항목 2개 이상 | 오늘 안에 전화·방문 |
| 추가 확인 (`watch`) | 15~39점 **또는** 미확인 항목 2개 이상 | 다음 통화 때 다시 보기 |
| 특이 표현 없음 (`ok`) | 15점 미만 | 기록만 |

r2까지의 라벨(긴급 · 오늘 확인 · 관찰 · 양호)을 제안서 용어(즉시 확인 · 추가 확인)에 맞춰 바꿨다. '양호'는 "문제가 없다"고 단정하는 말이라 **'특이 표현 없음'**(통화에서 걱정할 표현을 듣지 못함)으로 바꿨다. 항목 상태의 '양호'(§2)는 그대로다.

## 6. 이유 표시 형식

```
우선 확인 · 45점
· 식사 위험 (10)  "이틀째 밥을 못 먹었어"
· 식사 3일 연속 (+10)
· 수면 주의 (5)   "잠을 좀 설쳤지"
· 어제 미응답 (+10)
어려움: 식사 어려움 "혼자 차려 먹기가 힘들어서 그래"   ← 점수와 별개 (§8)
```

## 7. 이 값들은 가설이다

가중치와 기준선은 현장 검증 전 **시연용 가설**이다. 대신 `apps/api/tests/test_rules_sensitivity.py`에서 점수 하나씩 ±5로 바꿔도 상위 순위가 크게 흔들리지 않는지 확인하고, 그 결과를 `docs/평가/`에 남긴다.

## 8. 어려움 유형 (r2.1, 점수와 별개)

항목 상태가 "무엇이 얼마나 나쁜가"라면, 어려움 유형은 **"지원이 필요할 수 있는 사정"**이다. 제안서 3.나.2의 구분 — "아직 밥을 안 먹었어요"(미식사)와 "먹을 게 없어서 밥을 못 먹었어요"(식사 어려움 → 지원 필요) — 을 여기서 한다.
점수와 단계에는 **넣지 않는다**(같은 '식사 주의'라도 점수는 같다). 생활지원사 화면의 '어려움'과 복지서비스 연계(F11)의 입력으로만 쓴다.

| 유형 (키) | 예 | 아닌 것 |
|---|---|---|
| 식사 어려움 (`meal_difficulty`) | 먹을 게 없어, 반찬 살 돈이 없어, 혼자 차려 먹기 힘들어, 장 보기가 힘들어, 반찬이 없어 | 아직 안 먹었어, 입맛이 없어 |
| 수면 문제 (`sleep_problem`) | 며칠째 잠을 못 자, 잠이 안 와, 밤새 뒤척였어, 한숨도 못 잤어 | 잠을 좀 설쳤어(수면 주의만) |
| 도움 요청 (`help_request`) | 도움이 필요해, 도와줄 사람이 없어, 누가 좀 와 줬으면 | 119, 살려줘, 도와줘 → §3 안전 신호 |
| 외로움 (`loneliness`) | 외로워, 아무도 안 와, 말할 사람이 없어 | 안 외로워 |

- 규칙(`domain/needs.py`, 띄어쓰기·문장부호 무시)으로 먼저 찾고, AI가 찾은 것은 **인용이 답변 원문에 있을 때만** 더한다. 규칙이 찾은 것은 AI가 지우지 못한다.
- 한 통화의 어려움은 유형마다 처음 나온 인용 하나로 모은다(`Assessment.needs`). 어르신 상세의 복지 연계는 최근 7일 어려움을 쓴다.
- **식사 재질문**: 식사 질문에 '못/안 먹음'(주의·위험)이라고 했는데 식사 어려움도 이유("입맛이 없어서" 등)도 없으면, 한 번만 "아직 식사 전이신가요, 아니면 식사하기 어려운 이유가 있으신가요?"라고 묻는다. 큰 버튼은 '아직 식사 전이에요'(어려움 없음) · '먹을 게 없어서 못 먹었어요' · '혼자 차려 먹기 힘들어요'(식사 어려움). 다시 묻기 2회 한도에 들어가고, 이미 기록한 식사 상태는 내리지 않으며, 대답이 무엇이든 다음 질문으로 넘어간다.
