## 실행·갱신·재검토

저장소 밖 Python 가상환경에 `apps/api/requirements.txt`, 웹·앱에 각각 `npm ci`로 의존성을 설치한다.
기존 `scripts/dev-up.sh`로 API·웹·앱을 시작하고 서버 로그의 PIN으로 생활지원사 웹에 로그인한다.
공공데이터 화면: `/staff/public-data`. 기존 어르신 상세·통화 상세에 지원 후보가 나온다.

인증키는 `DATA_GO_KR_SERVICE_KEY` 환경변수 또는 Git 제외 파일 `공공데이터포털 api 키.txt`로만 읽는다.
다음 명령은 `apps/api`에서 실행한다.

```bash
python scripts/sync_public_data.py --all
python scripts/sync_public_data.py --province 세종특별자치시
python scripts/review_welfare.py                 # 신규·내용 변경 검토 대기 원문
python scripts/review_welfare.py WLF00002572     # 원문과 기존 검토 조건 확인
python scripts/smoke_welfare.py                 # 임시 DB + PIN 로그인 + 5문항 + 급식 후보
```

목록 건수·고유 ID·페이지가 완전할 때만 캐시를 원자적으로 교체한다. 특정 시도 갱신은 다른 지역·중앙부처의 확인일을 바꾸지 않는다.
목록 누락은 종료 확정이 아니라 확인 필요 상태다. 실패하면 기존 파일을 보존하고, 실행 중 손상에는 마지막 정상 값을 사용한다.
재시작 시 캐시가 유실되거나 손상됐고 마지막 정상본도 없다면 지자체 후보를 보류한다. 기본 21건의 예전 지자체 사업을 자동으로 되살리지 않는다.

검토 편입에는 `--decision include --needs <유형> --reason <이유> --evidence <실제 원문 구절> --check <기관 확인 조건>`이 필요하다.
`--region`, `--min-age`, `--max-age`를 생략하면 기존 제한을 유지한다. 조건이 바뀌었다면 해당 인자로 명시적으로 고친다.
연령 제한 해제는 `--clear-age-limits`로 명시한다. 내용을 읽지 않고 기존 검토를 자동 승계하지 않는다.
검토는 기술적 원문 검토이며 기관의 자격 심사나 선정 확정을 뜻하지 않는다.

## 남은 문제·검증 한계

- 실제 공공데이터 API 인증키가 제공되지 않아 실서버 재수집은 하지 않았다. 기존 캐시에 없는 연락처·잘린 원문은 재수집 전까지 복원되지 않는다. 가짜 전화번호·조건으로 채우지 않는다.
- 소득·장애·가구·거동·중복수혜 등은 현재 확인할 정보가 부족하다. 나이·지역과 별개로 모든 후보에 신청 자격 확인 필요를 표시하고 최종 선정은 기관이 확인한다.
- KOSIS 원본 Excel과 최신 공식 행정구역 전체 코드표를 대조하지 못했다. 제공 자료 밖의 새로운 개편·명칭은 추가 대응표 검토가 필요하다. 통계·후보 자료가 공식 원본의 최신성을 보장하지 않는다.
- 사회복지시설 API는 오퍼레이션·실데이터 검증이 끝나지 않아 시설 연결 기능은 미구현이다.
- 앱이 열린 동안의 시스템 알림은 최신 main 기능을 유지한다. 완전히 종료되거나 OS가 정지시킨 앱의 수신은 원격 푸시·전화망이 없어 보장할 수 없다.
- 담당자 PIN 인증은 유지했지만 기관별 계정·역할·어르신 기기 인증 등 실운영용 권한 체계를 완성한 것은 아니다.
- 실제 Ollama 모델, 실제 마이크·휴대폰·배경 수신은 확인하지 않았다. 브라우저 통합은 가짜 음성·규칙 판정으로 검증했다. 일반 AI 문장 전체의 사실성을 보장하지 않는다.
