- 한국사회보장정보원 중앙부처복지서비스: https://www.data.go.kr/data/15090532/openapi.do

- KOSIS: `kosis_households.json`, 2025년 246행. 원본 파일명과 기준연도는 보존한다. 원본 Excel은 제공 ZIP에 없다.
- 조회 4,828건이라는 수치는 제공자의 수집 기록이다. 전국 4,828건 원본이나 API 인증키는 이 저장소에 없다.
- 원문 사업은 가공 전 스냅샷을 보존한다. 데이터별 이용허락 조건은 공식 제공 페이지에서 확인한다.

## 후보 선별·신청 자격

`welfare_reviews.json`에 134건의 내용 해시, 편입·제외, 직접 지원 목적, 연령 범위, 확인할 조건과 검토 이유를 남겼다.
현재 107건은 직접 생활지원 후보, 27건은 제외다. 장례·종사자 수당·일자리 활동비·청년 주거·학생 지원을 일반 돌봄 후보에 넣지 않는다.
외로움에 의료 동행·밑반찬을 자동 연결하거나 수면에 `심리`라는 단어가 있는 사업을 무조건 연결하지 않는다.
급식소 운영사업도 주민이 실제 식사를 받을 수 있으면 후보에 남긴다.
이 검토는 Codex가 동봉 원문을 읽어 수행한 기술적 검토이며 기관의 신청·선정 심사나 사람의 최종 승인을 뜻하지 않는다.

나이는 원문에서 확인한 신청 연령 범위 비교에만 사용한다. 개인 위험 점수·단계는 바꾸지 않는다.
복수 대상·예외가 있는 나이 조건은 단일 범위로 단정하지 않는다. 소득·장애·가구·거동·중복수혜 정보는 추측하지 않고 전부 `신청 자격 확인 필요`로 표시한다.
자격이 확인되었다고 단정하는 UI는 없다. 사용자가 말한 어려움과 지역이 같아도 자동 신청하지 않는다.
일반 노인에게 부적합한 중장년 사업(WLF00005663)은 기본 40~64세 범위로 제한한다. 예외 인정 가능성은 기관에 별도 문의한다.

## 신규·변경 사업 검토

상세 원문의 내용 해시가 검토 당시와 다르면 추천에서 제외한다. 신규 사업도 동일하다. 기존 검토를 자동 승계하지 않는다.
`apps/api`에서 다음 명령으로 원문을 확인한다. 검토 기록을 바꾼 뒤 테스트를 실행하고 diff를 검토한다.

```bash
python scripts/review_welfare.py                 # 검토 대기 원문
python scripts/review_welfare.py WLF00002572     # 한 사업 원문
# 원문 확인 후 편입 예시 (evidence는 실제 원문 구절이어야 한다)
python scripts/review_welfare.py WLF00002572 --decision include --needs meal_difficulty --reason '주민에게 실제 급식 제공' --evidence '저소득 재가노인 식사' --check '소득·거동·중복수혜 조건 기관 확인' --min-age 60
```

## 지역·KOSIS

원본 지역명과 비교용 이름을 별도로 보관한다. 시도는 표준 코드로 비교하고 시군구는 같은 시도 안에서만 비교한다.
광주·전남을 합친 원문 지역명은 제공 KOSIS의 하위 지역 계층과 원문 담당기관으로 대응했다. 모호한 합산 지역은 보류한다.
새 행정구역의 법적 적용일이나 전체 시군구 코드표를 인증하는 자료는 아니다. KOSIS 계층에 없는 새 지역은 대응표 확인이 필요하다.
KOSIS의 `aggregation_level`은 원문 `level`과 구분한다. 광주·전남을 각각 시도 수준으로 비교하면 시도 17개의 가구 합계가 전국값과 일치한다.
생활지원사 웹 → 공공데이터 화면에서 같은 계층만 비교한다. 가구 수를 사람 수로 바꾸거나 계층끼리 합산하지 않는다. 개인 점수에는 사용하지 않는다.

## 갱신·누락 정보

인증키는 `DATA_GO_KR_SERVICE_KEY` 환경변수 또는 Git 제외 파일 `공공데이터포털 api 키.txt`로만 읽는다. 키를 API 응답·로그·저장 JSON에 쓰지 않는다.

```bash
python scripts/sync_public_data.py --all
# 특정 지역만 갱신 (다른 지역·중앙부처 자료의 확인일은 보존)
python scripts/sync_public_data.py --province 세종특별자치시
```

전체 페이지의 건수·고유 ID가 일치할 때만 완료로 인정한다. 기존 사업도 상세 재조회하며 목록에서 빠진 ID에는 미확인 상태를 남겨 이전 기본 자료가 다시 추천되지 않게 한다.
목록에서 빠졌다는 사실만으로 사업 종료를 확정하지 않는다. 상세 실패·페이지 누락·전체 건수 변동 시 기존 파일을 유지한다. 임시 파일을 원자적으로 교체한다.
앱은 실행 중 마지막 정상 캐시를 사용한다. 재시작 시 캐시가 손상됐고 정상본도 없으면 지자체 후보를 보류한다.  사업별 `checked_at`을 표시한다. 신규·변경 사업은 검토 대기다. 중앙부처 목록은 이 지자체 API 갱신 대상이 아니므로 기존 확인일을 유지한다.
원문 연락처는 중첩 XML을 포함해 수집한다. 새 조회는 원문을 400자로 자르지 않는다. 공유 자료의 기존 잘린 원문·연락처 누락은 인증키로 재조회해야 복원할 수 있다.
확인할 수 없는 전화번호·조건은 생성하지 않는다. 누락은 미제공으로 표시하고 공식 복지로 링크를 제공한다.
`checked_at`은 수집일이며 원본 기관의 최종 내용 수정일을 보장하지 않는다.

사회복지시설 API는 정확한 오퍼레이션과 실데이터 검증 전이어서 기능으로 연결하지 않았다. 시설 연락처나 기관을 만들어 넣지 않는다.
